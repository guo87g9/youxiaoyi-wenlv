**沙箱内为什么推不了**（实测，不是没试）

| 途径 | 实测结果 |
|---|---|

| SSH | `~/.ssh` 为空，无私钥 |

这四项都指向同一个结论：**凭据必须由你在自己账号下产生，我拿不到，也无法代你授权。**

**你只需一步：给我一个 PAT**

在浏览器登录 GitHub ≠ 沙箱拿到凭据。两者是隔离的：你登录的是自己电脑上的浏览器，
而沙箱是个独立容器，`gh`、`git credential`、连接器三条路都没有你的登录态
（连接器实测返回 `Connector "github" is not authorized for this user or project`）。

最短路径（30 秒）：

1. 打开 https://github.com/settings/tokens?type=beta （Fine-grained token）
   或 https://github.com/settings/tokens （Classic token，勾 `repo` 即可）
2. 生成 token，把 token 值发给我（或只在本机用，见下方替代方案）
3. 我收到后直接跑：`bash tools/push_github.sh guo87g9l/<仓库名> <token>`
   脚本会先校验 token → 推送 → 回读远端确认 → **把 token 从 git config 里摘掉**

**不想给 token 的替代方案**：把 `/workspace/youxiaoyi-wenlv` 整个目录拷到本机，
用 Git Credential Manager 或 SSH key 推送（你本机已登录 GitHub，直接推即可）：

```bash
bash tools/push_github.sh git@github.com:guo87g9l/<仓库名>.git
```

之前担心"白名单没配导致地图发白"，实测是误判：

```bash
# curl 直接请求会 403，但这是天地图对「浏览器端 key」的保护，不是白名单问题

```

用真实浏览器打开交付件，进入「护照」页（地图所在页）实测：

| 检测项 | 结果 |
|---|---|
| 天地图瓦片请求 | **16 个请求全部 200** |
