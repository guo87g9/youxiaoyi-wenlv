# 邮小驿 · 微信小程序工程

AI 邮驿智慧导游 —— 「运河数谷 智创未来」人工智能 OPC 创新创业大赛 · 赛道二（AI+产业 / 文旅板块）

## 一、怎么跑起来

1. 安装「微信开发者工具」（稳定版即可）
2. 导入项目 → 目录选本文件夹 `mini`
3. AppID 填自己的（个人可申请测试号），或先用「测试号 / 游客模式」
4. 直接编译，五个页面开箱可用

> 工程已内置 `project.config.json`，`urlCheck` 已关闭；**全程不发网络请求**，不需要配置服务器域名。

## 二、三个数据文件，别改错

| 文件 | 内容 | 谁生成 |
|---|---|---|
| `utils/db.js` | 景点 17 / 知识库 201 / 非遗 5 / 路线 5 / 美食住宿交通 | **`tools/sync_mini.py`** 从网页版 `app/data.js` + `app/data-kb.js` 生成 |
| `utils/qa.js` | 四层检索引擎（与网页版同一份源码） | 从 `app/shared/qa.js` 复制 |
| `utils/ui.js` | 图标 / 渐变色 / 讲解员分工 / 邮戳名 | **`tools/gen_mini_ui.py`** 生成 |

**不要手改 `db.js` 和 `ui.js`** —— 下次同步会覆盖。要加景点或问答，改网页版 `app/data*.js`，然后跑：

```bash
python3 tools/sync_mini.py && python3 tools/gen_mini_ui.py
node tools/mini_test.js      # 36 项页面逻辑自测
```

这样「一套内容、多端分发」是真的成立，而不是宣传话术：网页版加一条知识库，小程序重新同步后立刻问得到。

## 三、页面

| 页面 | 路径 | 做了什么 |
|---|---|---|
| 首页 | `pages/index` | 17 处景点按四类筛选，分类数量现算；点卡片名 → 跳问答并自动提问 |
| AI 讲解 | `pages/guide` | 5 位讲解员，各绑一个景点；提问走检索引擎并带景点作用域（`spotId`），问「门票多少钱」不会串到别的景点 |

## 四、问答为什么答得准

`utils/qa.js` 就是网页版那份四层引擎，18KB，纯 JS、无 DOM 依赖，`require()` 直接可用：

1. **归一化** — 全半角、简繁、同义改写（"咋去"→"怎么去"）、语气词剥离
2. **实体识别** — 137 个景点/别名词条，最长优先（"高邮湖"不会被"湖"吃掉）
3. **意图归类** — 16 类意图（门票 / 时间 / 交通 / 美食 / 停车 / 无障碍 …）
4. **加权打分** — 意图契合 + 实体契合 + 问法 bigram 重合 + 字符召回 + 整句命中 + 残句覆盖

离线评测 **934/934 = 100%**（`node tools/qa_eval.mjs`，用知识库自身的 934 条问法回灌）。

几个踩过的坑，写在这里免得重踩：

- `["有什么","玩什么"]` 这种同义替换**不能**放——「有什么特产」会被改成「玩什么特产」，直接答错类目。裸「有什么」只在句尾无宾语时才改。
- 意图词不能无脑从问句里挖掉。`鸭蛋` 在 food 意图表里，但用户问「高邮咸鸭蛋为什么好」时它是**内容**；挖掉就只剩「高邮咸为什么好」，永远匹配不到「咸鸭蛋为什么出名」。规则：命中实体表 / 含数字 / 长度 ≥3 且不含疑问字形的词，只登记意图、保留在句内。
- 短问法被长问句包含不能算「整句命中」。「抗战馆里面有什么」曾被别条的「里面有什么」以满分奖励截胡。现在要求占问句 ≥60%。

## 五、语音

小程序没有浏览器的 `speechSynthesis`，要接官方「微信同声传译」插件才能真发声。

在 `app.json` 顶层加：

```json
"plugins": {
  "WechatSI": {
    "version": "0.3.1",
    "provider": "wx069ba97219f66d99"
  }
}
```

未声明时点语音按钮会弹说明，不报错，其余功能正常。

## 六、体积

主包 **256 KB**（限 2 MB）。其中 `db.js` 112 KB、`qa.js` 18 KB。音频不打包进小程序（共 15 MB，远超限制），语音走插件实时合成。
